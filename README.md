# Rover Type A controller

План следующего этапа: [лёгкая VLM, зрение и голос ровера](docs/vision-assistant-plan.md).
Это план исследования и реализации, а не уже работающая функция.

Локальный веб-пульт для ровера типа A из файла `/Users/michael/Downloads/Ровер тип А.pdf`.

## Как управлять

1. Включите батарейный отсек на машинке.
2. Откройте пульт по локальному HTTP-адресу.
3. В поле `Шасси` уже стоит адрес нашего ровера: `http://192.168.2.23`.
4. Нажмите `Проверить`. Камера подставится из `/status` или как следующий IP-адрес.
5. Поставьте машинку на подставку со свободными колёсами и нажмите «Определить колёса».
6. Для каждого `M1`-`M4` отправьте положительный импульс, укажите физическое колесо и направление движения его верхней части. После четырёх шагов нажмите «Применить карту».
7. Управляйте стрелками на экране или клавишами `W A S D`, `Q E`, `Space`.

`Q/E` выполняют разворот на месте всеми четырьмя колёсами: левая и правая стороны получают противоположные команды. Поворот имеет приоритет над одновременно удерживаемыми `W/A/S/D` и стрелками. После отпускания клавиши поворота продолжается удерживаемое направление. Карта моторов и инверсия учитываются и при поворотах.

Если при нажатии только Q или E физически вращаются лишь задние колёса, нужно проверить соответствие M1-M4 колёсам и питание передних моторов. Код не определяет физическое расположение моторов автоматически.

## Калибровка

Начальная карта M1=переднее левое, M2=переднее правое, M3=заднее левое, M4=заднее правое — предположение, а не определённая разводка. Даже если движение вперёд и боком работает, правильность карты не доказана: перестановка по диагонали сохраняет эти команды, но меняет разворот.

В мастере настройки нет предвыбранных ответов. «Импульс» посылает только выбранному мотору +45 на 350 мс, остальные получают 0. Лево и право определяются по направлению носа ровера, не наблюдателя. Следите за вращением всего колеса, а не отдельных роликов. Если верх колеса при положительном импульсе движется к корме, мастер выставит инверсию.

Старая карта сохраняется до применения всех четырёх наблюдений; «Отмена» оставляет её без изменений. Во время мастера обычное движение отключено. Повторный тест не начнётся, пока не завершится текущий запрос и импульс. Профиль с повторяющимися положениями не допускается; при ручном выборе занятого положения два мотора меняются назначениями. Для перенастройки используйте устойчивую подставку со всеми колёсами в воздухе.

Кнопка со стрелкой вниз скачивает `rover-02-wheels.json`, со стрелкой вверх — загружает его. Файл переносит только карту колёс нашего ровера, не адреса, мощность или состояние камеры. Заполненную карту можно отправить вместе с наблюдениями для дальнейшей диагностики.

Если после подтверждения карты ровер продолжает дёргаться на месте, нужны видео колёс при отдельном Q/E и фото их расположения. По HTTP-ответу нельзя установить физическую ориентацию колёс, сцепление или фактическую скорость моторов. Увеличение мощности без этих наблюдений не исправляет ошибочное назначение колёс.

## На другом компьютере

```sh
git clone git@github.com:michael4way-ctrl/rover.git
cd rover
python3 -m http.server 5173
```

Откройте `http://127.0.0.1:5173/`. Если репозиторий уже скачан, обновите его командой `git pull --ff-only`. Для управления компьютер должен быть в сети ровера. Настройки калибровки сохраняются в браузере и через Git не переносятся; используйте экспорт/импорт карты.

## Что делает пульт

- `GET /wheels?m1=...&m2=...&m3=...&m4=...&timeout=...` отправляет мощности от `-100` до `100` (GET с параметрами поддерживается по инструкции ровера).
- `GET /stop` останавливает шасси. GET-команды изменяют состояние робота; не открывайте их для проверки связи.
- `POST /servo` поворачивает камеру в диапазоне `0`-`180`.
- `POST /buzzer` отправляет тон или мелодию.
- `GET /sensors` читает сонар и датчики линии.
- Камера использует `/snapshot`, `/flash?v=...` и поток `:81/stream`.

Пульт повторяет команды движения, пока удерживается кнопка или клавиша. Это нужно потому, что `timeout` у ровера всегда останавливает движение автоматически.

## Задержки связи

- Одновременно отправляется только одна команда колёс. Пока она выполняется, сохраняется только последнее выбранное направление.
- STOP удаляет неотправленные направления и отправляется после завершения текущего запроса. Ожидание ответа на движение ограничено 1200 мс; при ошибке управление отключается до повторной проверки подключения.
- Отмена HTTP-запроса не отменяет команду, уже дошедшую до прошивки. При плохой сети остановка также может запаздывать; таймер движения робота остаётся включённым.
- GET-команды с отключённым кешированием избегают дополнительного CORS-запроса, необходимого для POST с JSON.
- Видео включается вручную кнопкой Stream, выключается квадратной кнопкой рядом с Shot. Shot получает один кадр.
- Автоопрос датчиков выполняется раз в секунду и пропускается во время движения. Незавершённые опросы не накапливаются.
- Поле «Ответ» измеряет полный HTTP-ответ, включая тело; это не ICMP ping.

Проверки логики отправки без обращения к роботу: `node --test tests/controller.test.cjs`.

## Ограничения

- Не отправляйте команды чаще одного раза в 50 мс.
- В этой версии управление заблокировано для всех шасси, кроме `192.168.2.23`.
- Камера также заблокирована на адрес нашего комплекта: `192.168.2.24`.
- Мощность ниже примерно `30` может не сдвинуть мотор.
- `valid: false` у сонара означает, что эхо не вернулось.
- Порог линии нужно подобрать на своей трассе.
